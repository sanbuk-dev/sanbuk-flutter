# Sanbuk Flutter SDK

پلاگین رسمی فلاتر برای [سنبوک](https://sanbuk.com) — نمایش تبلیغ در رسانهٔ ناشر، در مدل CPA.

**[English guide →](README.md)**

> **وضعیت: اولین نسخهٔ پیش‌نمایش — فعلاً فقط اندروید.** بنر، نیتیو، اینترستیشیال و پاداشی هر چهار کار می‌کنند و رندرشان با اس‌دی‌کی نیتیو اندروید است. iOS وقتی می‌آید که لایهٔ رندر آن اس‌دی‌کی ساخته شود؛ تا آن روز این پلتفرم اعلام نمی‌شود، چون پلتفرمی که پیش از کارکردن اعلام شود یعنی کرش روی آیفون یک نفر.

## نصب

```yaml
dependencies:
  sanbuk_flutter:
    git: https://github.com/sanbuk-dev/sanbuk-flutter.git
```

بعد یک خط در `android/build.gradle.kts`، داخل `allprojects { repositories { … } }`:

```kotlin
maven { url = uri("${rootDir}/../../android/repo") }   // مسیر پوشهٔ repo داخل پلاگین
```

این خط برای این لازم است که هر اپ وابستگی‌هایش را خودش resolve می‌کند: اس‌دی‌کی نیتیو به‌صورت
یک مخزن Maven تک‌آرتیفکتی داخل همین پلاگین سفر می‌کند و Gradle تا وقتی اپ شما اسمش را نبرد
آنجا را نگاه نمی‌کند. روزی که `ir.sanbuk:sdk-android` روی یک مخزن عمومی منتشر شود این خط
حذف می‌شود و هیچ‌چیز دیگری در یکپارچه‌سازی شما تغییر نمی‌کند.

اگر پروژه‌تان مخزن‌ها را در `settings.gradle.kts` و زیر `dependencyResolutionManagement`
نگه می‌دارد، همان خط را آنجا اضافه کنید.

## استفاده

```dart
// یک‌بار، در شروع برنامه
await Sanbuk.init(mediaCode: 'YOUR-MEDIA-CODE');
```

**ما رسمش می‌کنیم** — ویجتی که تبلیغ را می‌گیرد، رندر می‌کند، نمایش را می‌شمارد و کلیک را می‌برد:

```dart
const SanbukAdView(placementCode: 'HOME-TOP')
```

**خودتان رسمش کنید** — همان تبلیغ به‌شکل داده، با استایل ویجت‌های خودتان:

```dart
final ad = await Sanbuk.loadAd('HOME-TOP');   // تیتر، تصویر، دکمه، رنگ‌ها
if (ad == null) return const SizedBox.shrink();

// ...با ویجت‌های خودتان رندرش کنید...
ad.recordImpression();   // وقتی واقعاً روی صفحه است
// ...و روی تپ:
ad.click();
```

`null` بودن تبلیغ یک پاسخ عادی است، نه خطا: کمپینی مچ نشده، بودجه تمام شده، یا سقف امروزِ
جایگاه پر است. فضا را جمع کنید یا محتوای خودتان را بگذارید — هرگز خطا نشان ندهید.

رسم‌کردن با دست خودتان دو تعهد دارد، و دلیل وجود رندر پیش‌فرض هم همین است: `recordImpression()`
را فقط وقتی صدا بزنید که تبلیغ واقعاً روی صفحه است، و آن را به‌عنوان تبلیغ برچسب بزنید. متن
برچسب را از `ad.disclosureLabel` بگیرید.

**تمام‌صفحه** — اول لود، بعد نمایش؛ چون لحظه‌ای که ارزش قطع‌کردن دارد معمولاً همان لحظه‌ای
نیست که وقت یک رفت‌وبرگشت شبکه را دارید:

```dart
final ad = await SanbukFullscreen.load('LEVEL-END');
// ...بعداً، هر وقت اپ شما تصمیم گرفت...
await ad?.show();
```

`SanbukFullscreen.loadRewarded` همان نسخه‌ای است که کاربر خودش خواسته. قواعد قطع‌کردن — هیچ
تبلیغی حین کولد استارت، هیچ تبلیغی پشت‌سرهم، سقف در هر نشست، و دکمهٔ بستن بعد از چند ثانیه —
در اس‌دی‌کی نیتیو اعمال می‌شوند، نه اینجا؛ پس روی همهٔ پلتفرم‌ها یکسان‌اند و یک پوسته
نمی‌تواند دورشان بزند.

## این پکیج چیست

عمداً یک بایندینگ نازک. مچینگ، پیسینگ، سقف تکرار، دورهٔ آزمایشی و بودجه روی سرور سنبوک
هستند؛ قاعدهٔ دیده‌شدن، صف آفلاین ایمپرشن و قواعد قطع‌کردن در اس‌دی‌کی نیتیو. این پکیج
می‌پرسد، رسم می‌کند، و گزارش می‌دهد.

نسخه‌ای که روی گوشی‌ها می‌رود ماه‌ها فریز است، پس قاعده‌ای که داخل یک پوسته سفت شود از چند
بار تغییر تصمیم عمر بیشتری می‌کند — و باید برای هر پوستهٔ دیگر دوباره نوشته شود، جایی که
نسخه‌ها از هم دور می‌افتند.

## اجرای نمونه

```bash
cd example && flutter run
```

`flutter test` تست‌های واحد را روی یک کانال قلابی اجرا می‌کند. تنها تستی که به دستگاه واقعی
نیاز دارد جداست، چون کانال قلابی هر جوابی را که به او بگویند می‌دهد و نمی‌تواند اسم متدی را
که سمت کاتلین جور دیگری نوشته شده بگیرد:

```bash
cd example && flutter test integration_test
```
